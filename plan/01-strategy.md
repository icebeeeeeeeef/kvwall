# 01 策略：方向、证据、阶段、对齐

## 1. 背景与约束

- 985 本科；字节火山引擎对象存储实习（偏边缘工作，作为背书而非硬核证明）；后端与存储基础扎实程度中等；无深度学习 / 强化学习基础；无科研与论文。
- 目标：进入国内推理团队中负责 KV cache 的组（分层存储、IO 优化、PD 分离下的池化等），以此为入口进入 AI infra；长期目标是核心 infra 团队（Moonshot / DeepSeek 一类），作为第二跳而非第一跳。
- 资源：有充足的时间和可用于租用云上多卡多机的资本。
- 已知风险：预训练算法侧几乎不可能；框架层窗口正在关闭；单纯的分层存储正在被商品化。

## 2. 方向定义

不把自己定义为「做 KV cache 的」，而是「**做 LLM 推理的内存层级与数据搬运的**」。包含 KV cache 分层、权重加载、PD 传输、跨实例共享、以及未来 RL 系统里的 weight sync。

三个理由：

1. 单纯的分层存储正在商品化（Mooncake、LMCache、HiCache、vLLM tiered offloading、云厂商产品）。剩下难的是 cache-aware 调度、PD 下的传输、与调度器的耦合。
2. 模型架构在变：MLA 压缩 KV、混合线性注意力让部分层没有传统 KV、稀疏注意力让 kernel 只读部分 block。问题从「容量」变成「放置、调度、搬运」。
3. agentic workload 把重心往上抬：巨大共享前缀、多轮、子 agent，核心问题是调度器怎么感知 cache、请求怎么路由、何时 offload 何时重算。

因此从第一天起要往两头伸手：**往上**碰调度器，**往下**碰 kernel 接口（paged KV 如何被 attention kernel 读）。不呆在存储那一层。

## 3. 迁移逻辑：存储 → KV cache

| 存储系统概念 | KV cache 对应 |
|---|---|
| 多级存储（内存 / SSD / 远端） | HBM → pinned DRAM → NVMe / 云盘 → 远端池 |
| 元数据管理 | prefix radix tree / 内容寻址的 block hash |
| 缓存驱逐、命中率、尾延迟 | LRU / ARC、分层命中率、TTFT p99 |
| IO 路径、零拷贝、RDMA | PCIe DMA、pinned memory、GDS、NIXL / Mooncake Transfer Engine |
| 生产运维：SLO、热点、故障 | SLO 约束下的容量规划、router 瓶颈、tier 失效 |

叙事：「我知道存储系统在生产里长什么样，KV cache 是这个问题在 LLM 里的形态。」不要把实习说成打杂。

## 4. 证据哲学

### 4.1 一根线

个人项目、PR、博客不是三件独立的事，而是一根线：**平台产生测量和发现 → 发现变成 PR → 测量变成文章**。三样互为证据。

- 项目 = 平台 + 闭环（提供闭环强度）
- PR = 落在引擎 KV 路径或 tier 框架里的修改（提供可验证性）
- 文章 = 有自己测出来的图的测量报告 / 源码拆解（提供可读性和传播）

### 4.2 含金量权重（核心团队读一个个人项目时的隐含评分）

| 权重 | 维度 | 说明 |
|---|---|---|
| ~25% | 测量方法论成立 | 预热、方差、尾延迟、变量隔离、数字离硬件天花板多远且能解释 |
| ~25% | 文档里没写的发现 | 反直觉指标、工程摩擦、默认参数在此负载下为何是错的 |
| ~20% | 问题真实 | 负载来自真实 trace、SLO 有定义、资源约束真实 |
| ~10% | 决策链可追溯 | 每个设计选择指回一条测量；决策日志 |
| ~10% | 至少一处打到底 | profiler / kernel 调用 / 驱动层面 |
| ~10% | 接入真实系统、可复现 | 真实引擎而非模拟器；脚本、配置、数据齐全 |

低权重（不为它们花时间）：功能数量、支持几个后端、架构图、策略新颖性、代码量、star 数、与 Mooncake 比绝对性能。

### 4.3 不算证据的东西

- 看完教材、上完课程
- 跟教程跑通一个 demo
- 「我读过 xx 源码」（不可验证，必须转成 PR 或文章）
- 「学习能力强」
- 概念科普类文章（「什么是 KV cache」）——负分

### 4.4 「玩具」判定清单

| 玩具信号 | 非玩具信号 |
|---|---|
| 模型在该硬件上内存根本不紧 | 生产真在跑的模型形态，内存真紧 |
| 合成负载、固定长度 | 真实 trace 或 trace 派生分布 |
| 悬崖出现在并发 3 | 悬崖出现在几十个会话 |
| TP=1，分片汇聚不存在 | TP≥2 |
| 跨节点走 TCP | 跨节点走 RDMA |
| 饱和点吞吐 | SLO 约束下的容量 |

规模只是放大器，玩具感的真正来源是方法论。

## 5. 阶段规划

| 阶段 | 相对时间 | 目标 | 产出 | 强度校准 |
|---|---|---|---|---|
| 0 地基 | 0–2 月（含 3 周预备期，见 `09`） | 有资格产出证据 | 主引擎 KV 路径源码级理解；CUDA runtime + 能读 paged kernel 接口（D-018）；平台骨架能跑 baseline 出图；几个熟悉流程的小 PR | 工程化低，学习强度满 |
| 1 实习证据 | 2–5 月 | 一个完整的闭环系列拿实习 | 主线 Part I（Ch0–Ch4）；1–3 个落在 KV 路径的 PR；每章一篇有图的文章；源码拆解 1–2 篇 | 闭环强度 > 工程化强度；不做完备 API / CI |
| 2 目标团队证据 | 6–15 月 | 生产经验 + 生态贡献 | 实习生产故事；Part II / III；从数据里长出的组件 upstream 到 JD 点名系统；一次 RDMA / 多机的硬测量 | 工程化强度与稀缺度上升，闭环仍完整 |

证据构成权重：

- 阶段 1（实习）：引擎理解 40% / 测量线 40% / PR 20%
- 阶段 2（目标团队）：生产经验 50% / 生态贡献 30% / 硬测量 20%

时间窗口比闭环完美更重要：三四个月内有可见贡献就去投，不要等「做完」。

## 6. 生态对齐

- **主引擎：vLLM**。其 tiered KV offloading 框架（host 中心、fs / obj / p2p 二级层、out-of-tree tier 接口、per-tier 指标、KV events）是本项目的直接工作面；作者刚发布，测的 regime 是本项目的补集。
- **远端池：MooncakeStore**（vLLM 已集成 standalone 模式；也是 SGLang HiCache 后端）。保住 Moonshot 生态对齐。
- **对照臂：SGLang HiCache**，阶段 2 加入，保住广度并防止只懂一个引擎。
- **路由 / 编排：现成的**（Dynamo frontend、SGLang router、llm-d），不自建；不上 k8s 除非被迫。
- 进组时看组的位置：能碰 scheduler 的 KV cache 组 > 只碰存储的组。面试反问 KV cache 与调度器的边界、驱逐策略谁决定。
- 现实路径：大厂 / 中型公司推理或 KV 团队实习 → 1.5–3 年 ownership → 带生产经验和生态贡献跳核心团队。Mooncake / vLLM tiering 的活跃贡献者是唯一的直通路径。
- 备选入口：训练侧存储（checkpoint、数据加载、并行文件系统），与主线共享「数据搬运」内核，不并行推进。

## 7. 执行规则

1. **无测量不加功能**。每加一个东西，决策日志里必须有「因为测到了 X」。
2. **去掉论文的目标，保留论文的方法**。不追求新策略；受控变量、消融、方差是必需。
3. **负结果 + 解释 = 完成**。
4. **每章有边界声明**。
5. **一根线 > 五个碎片**。阶段 1 只做 Part I。
6. **项目投入有上限**。超过上限的时间给 upstream 和实习，不给平台美化。
7. **不假装有硬件**。RDMA / GDS 没实测就明说，附上准备程度。
8. **机制研究与生产声明分开标注**。

## 8. 长期路径

- **A 深耕**：KV cache → 引擎内存管理与调度 → 整个引擎（scheduler、PD、集群 router）。主线。
- **B 横移 RL 系统**：桥梁是传输引擎。KV cache → RDMA / 传输层 → weight sync → rollout 引擎管理 → 环境 / sandbox 编排。第二年开始搭桥。
- **C kernel**：能读、能 profile、能提需求；不作主线。

交叉点「内存层级 + 数据搬运 + 调度」是 T 型的那一竖。切换方向的证据 = 落在两个领域交界处、解决对方真实问题的产出。
