## 首个最小闭环要回答

- [ ] 本地 RTX 4060 的实际显存/驱动、OS/WSL 与可用工具；小模型能否正常服务一个请求？
- [ ] 选择一个可装下的 dense/GQA 开发模型（优先 0.5B～1.5B），固定 revision/tokenizer；不坚持 7B。
- [ ] 固定 vLLM 版本/commit、依赖和安装方式；审计实际 attention backend、dtype、prefix、chunked prefill 与 CUDA graph。
- [ ] 从 config 算权重和 KV 数量级；实际 KV 预算/运行时预留是多少？
- [ ] 用哪个现成客户端或薄适配实现多轮、固定输入 token/输出长度、gap、共享前缀和 seed？
- [ ] 冷、热、绕过/清空的命中证据如何取得？清理方式是否确实影响目标缓存？
- [ ] 会话/请求、首轮/后续轮、TTFT/TPOT/ITL、失败/超时和在途请求如何记录？客户端输出若按 chunk 合并，ITL 如何标注？
- [ ] 扫哪些安全的并发点，提前选什么 SLO/失败率阈值，如何判断样本不足？
- [ ] 最小 runner、manifest、原始结果和绘图入口落在哪里；能否按记录重跑？

首版只需以上事项有可执行的答案，不要求外部 KV connector、Mooncake、NIXL、多机和模型适配已经完成。

## Ch1–Ch3：由观测决定的下一步

- [ ] 退化来自 KV 容量/抢占，还是计算、排队或客户端？下一次最便宜的区分实验是什么？
- [ ] 引入 CPU 层前，在所钉版本确认实际接口、可用配置、块布局与完成/释放位置。
- [ ] GPU 命中、CPU 恢复、次级层恢复和重算如何区分；每层的 query/hit/bytes 分母是否一致？

- [ ] 回载与重算曲线是否真的交叉；没交叉/样本不足怎样报告？
