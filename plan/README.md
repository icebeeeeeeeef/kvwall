# 总体方案规划

本目录是项目的「宪法」：策略、主线、方法论、基础设施、JD 映射、参考资料、决策日志和开放问题。它是活文档——很多设计只在做到的时候才能做出来，所以这里写的是**方向、边界、规则和已知的约束**，不是实施细节。

初始化日期：2026-09-18。

## 文件

| 文件 | 回答的问题 |
|---|---|
| `01-strategy.md` | 为什么选这个方向；证据怎么构成；分几个阶段；对准哪些团队和生态 |
| `02-mainline.md` | 技术主线是什么；分几章；每章的最小配置、硬件层、trade-off、JD 命中 |
| `03-methodology.md` | 一个闭环怎么做、怎么算做完、指标怎么定义、文章怎么写、什么不能做 |
| `04-infra-and-budget.md` | 用什么硬件、什么软件栈、钉哪些版本、钱怎么花、环境怎么自动化 |
| `05-jd-map.md` | 目标岗位 JD 原文与章节映射；哪些不覆盖 |
| `06-references.md` | 直接相关的文章、系统、论文与阅读优先级 |
| `07-decision-log.md` | 已经做出的决定、理由、代价、复审条件 |
| `08-open-questions.md` | 还没有答案、需要在做的时候回答的问题 |
| `09-learning-roadmap.md` | 启动前的前置知识；每章开始前学什么；哪些在项目内实践、哪些只在项目外理解或小实操 |

## 阅读顺序

- 第一次读：`01` → `02` → `07`
- 开始动手前：`09` → `03` → `04` → `08`
- 每章开始前：`09` 对应章节 + `08` 相关问题
- 准备面试或写简历：`05`

## 维护规则

- 改变方向性的决定，先写进 `07-decision-log.md`，再改其他文件。
- 每章开始前，把该章相关的开放问题从 `08` 里挑出来；回答后记回 `07` 或该章的 writeup。
- 本目录不放数据、不放代码、不放实验结果。
- 文档里的数字若是估算，必须标「粗算」；正式数字只来自 `data/` 里带运行清单的测量。
